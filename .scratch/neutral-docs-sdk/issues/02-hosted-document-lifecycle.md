# 02: 无本地路径托管文档的新建、打开与持久化

## What to build

浏览器和 Qt 宿主通过公开 SDK 管理没有本地路径的文档。用户仍使用原有文件入口，宿主负责对象身份、名称、首次保存目标、另存后的对象切换和自动保存策略；编辑器负责空白内容、编辑与 DOCX 序列化。对应原需求第 2 项。

## Acceptance criteria

- [ ] 使用宿主提供的不透明对象标识、显示名称和内容完成新建与打开；本地路径可选，缓存路径不能成为对象身份。
- [ ] 新建、初次保存命名和目标、打开、最近文档、另存后采用副本或仅导出等决策交给宿主；创建工具不得先自行选择本地路径再调用宿主。
- [ ] 保存及自动保存提交当前托管对象；仅缓存写入、pending 或未确认提交均不得报告业务保存成功。
- [ ] 另存结果明确是否切换当前对象；仅导出的副本不改变当前对象、后续保存目标或当前 dirty 状态。
- [ ] 复用 ForaOffice 原有保存串行化、保存期间编辑、版本确认、dirty 和撤销规则；不重新设计这些语义。
- [ ] 宿主可配置自动保存及只读限制；菜单、快捷键、起始页和作用于托管文档的工具入口执行相同策略。
- [ ] 宿主取消、失败或不支持操作时不回退到本地行为；启动失败或取消不能绕过宿主擅自创建新对象。
- [ ] 独立运行模式及独立文件 CLI 保留自身文件契约；CLI 不能成为绕过托管对象保存策略的替代入口。
- [ ] 浏览器公开 SDK 与真实 Qt 宿主均验证无路径新建、打开、首次保存、再次保存、另存两种结果、取消和失败；保留现有保存并发回归。
- [ ] SDK 不内置报告、模板、项目字段等业务对象，也不复制独立应用实现宿主接入。
